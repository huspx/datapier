# Datapier UI 设计规范

## 1. 适用范围与依据

本规范从现有 [UI 设计稿](ui-redesign.html)、[UI 设计说明](ui-redesign.md)及其样式中整理，作为新增界面和既有界面调整的共同约定。保持数据库工作台原有的紧凑、平面、内容优先风格，不另建一套视觉语言。

- 本文维护跨功能的视觉、组件、文案和交互约定。
- [UI 设计说明](ui-redesign.md)维护具体功能的操作语义；本文第 8 节记录 MCP 待办的布局与状态要求。
- [HTML 设计稿](ui-redesign.html)是唯一交互示例入口，示例不连接数据库，不代表执行或认证成功。
- 原生界面使用公开 Tern SDK 元素和宿主主题；HTML 像素是对照基准，宿主控件皮肤和实际行为以原生验证为准。
- 工程与验证规则见[贡献指南](../CONTRIBUTING.md)，接口与权限边界见[0.2.0 技术方案](technical-design-0.2.0.md)。

## 2. 视觉原则

1. **内容优先**：连接名、对象、命令和结果是主体，装饰不能挤占工作区。
2. **平面分区**：用布局、间距、细分隔线区分区域；列表不套卡片，不用阴影制造多层容器。
3. **稳定层级**：标题、状态、摘要、详情、操作分层；禁止把独立字段连续拼成一行无间距文字。
4. **同义同形**：同一种状态、操作、选择和分页在不同功能里沿用相同表达。
5. **真实与克制**：不猜测结果、计数、权限、时间或成功状态；缺失信息显示“未记录”或“未知”。

## 3. 主题、字体与尺寸

### 3.1 颜色与字体

原生使用宿主语义 token；浏览器使用原稿的对应变量。禁止在业务组件里固定亮色、暗色或整块白底，也不全局重置宿主按钮和输入框。

| 用途 | HTML 对照 | 原生现有 token / 规则 |
|---|---|---|
| 主要文字 | `--fg` | `--t1` |
| 次要文字 | `--muted` | `--t3` |
| 面板与控件表面 | `--panel`、`--card` | 宿主 surface、`--card` |
| 分隔线 | `--border` | `--l2` |
| 选中、悬停 | `--selected`、`--hover` | `--tv-sel` 与已有 active 样式 |
| 强调、焦点 | `--accent` | `--accent` |
| 成功、警告、错误 | `--success`、`--warning`、`--error` | 沿用已有语义样式；状态同时有文字或形状 |
| 界面文字 | Geist / sans 回退 | `--sans` |
| SQL、Redis 命令、ID、数据 | `--mono` | `--mono` |

正文以 13px 为 HTML 基准，数据以 11px 为基准；对话框标题约 15px、中等字重，分区标题约 12px，辅助信息约 11px。不要把状态栏继承的 10px 字号带入完整任务界面。长名称允许断行或省略，完整值应能从详情或 tooltip 获取；命令保留换行，不使用界面字体展示代码。

### 3.2 尺寸与间距

| 项目 | 原设计基准与使用规则 |
|---|---|
| 常规图标按钮 | 28px 热区、14px 图标；tooltip 与可访问名称齐全 |
| 原生按钮 | 高约 28px，使用宿主 quiet / default / primary / danger 变体 |
| 行内元素间距 | 通常 6–8px，不依靠文本中的空格排版 |
| 字段与分区间距 | 字段约 12–14px，分区约 16px；保持同页一致 |
| 连接行 | 最小约 44px，主名与副行对齐，操作保留固定空间 |
| 数据行 | 约 35px；Redis key 行约 34–36px |
| 展开导航 / 窄轨 | 224px / 58px |
| 上下文 / 标签 / 分区导航 | 最小约 54px / 39px / 28px |
| 状态栏 | 高约 29px，仅承载简短状态和轻入口 |
| 对话框 | 最大约 720px，距工作区边缘至少 20px，正文滚动、头尾可达 |
| 对话框内边距 | 标题约 14px 20px，正文约 18px 20px，底部约 12px 20px；原生由 SDK 绘制 |

## 4. 组件与操作语义

### 4.1 列表、标签与状态

- 连接、资源、任务选择行左对齐，平面背景，无按钮边框、圆角或阴影；悬停与选中使用底色和明确焦点态。
- 分区标签沿用工作台下划线活动态，不采用胶囊按钮或大型彩色卡片。
- 主行显示用户可识别的连接名、资源名或操作标题；地址、数据库、时间和简短 ID 放在副行或详情。
- 不以 UUID 或原始枚举作为唯一标题。状态翻译为“待审批”“待认证”“执行中”“已完成”“已拒绝”“已过期”等可读文案。
- 普通数据字段不按内容自动着色。状态使用语义色时仍显示文字，不能仅靠红绿区分。
- 连接类型、Archery 来源和连接状态沿用已有图标及角标语义，不互相替代。

### 4.2 按钮与危险操作

- quiet 用于辅助入口、切换和图标动作；default 用于关闭、返回、刷新等常规动作；primary 用于当前步骤的明确提交。
- danger 表达真实破坏性操作，不能把“拒绝审批”误画成删除数据。
- 一个操作区域保持明确主次；主提交居右，次操作在前。不能把多个按钮无间距嵌入状态文字。
- 图标动作需有 tooltip 和可访问名称；认证、保存等表单主操作保留文字，审批行内的批准与拒绝使用具名图标按钮。
- 无权限、其他窗口控制、正在提交或详情尚未加载时禁用动作，并说明原因。禁用态不能只隐藏必要上下文。

### 4.3 对话框与轻浮层

- 认证、审批、任务浏览、详情等多步骤工作使用原生 `overlay`，从界面 layer 挂载。
- 轻浮层仅承载简短说明，例如查询结果来源与限制；不得把完整工作流嵌进状态栏的绝对定位容器。
- 对话框复用 SDK 标题、关闭、遮罩、滚动和 footer，不仿造另一套外壳，不再通过放开状态栏 overflow 容纳正文。
- 标题、正文和操作区分离。正文可滚动，短窗口下关闭和提交可达；长命令和表格只在各自区域滚动。
- 同时只呈现一个交互主对话框；从待办进入认证时交接到既有安全认证表单，不叠放两层表单。
- Escape 关闭当前对话框或最内层下拉；关闭待办不批准、不拒绝、不取消 Agent 任务。

### 4.4 详情与结构化数据

- 沿用任务详情的“标题与状态 → 摘要 → 命令 / 结果 / 错误”顺序。
- 摘要使用带分隔线的双列事实区，窄屏变单列。标签弱化，值完整可读。
- SQL / Redis 命令独立分区显示，绑定参数分开列出，不伪造插值后的执行文本。
- 完整请求、ID、digest、协议字段等技术诊断放在默认折叠的“完整诊断”中；首屏不直接铺原始 JSON。
- 任务详情使用创建时冻结的连接、数据库与执行信息，不能借用当前标签制造上下文。敏感字段不得进入通知、列表或诊断展示。
- 结果复用现有 grid 与分页器，页大小在翻页按钮之前。过期、释放、未知列和不完整结果明确说明，不能显示假成功或自动重执行。
- 统一分页候选为 20／50／100／200／500／1000，并保留当前配置的自定义页大小。未知总数只显示当前页，安全实时源提供显式“统计总数”；单次结果只翻阅仍保留的数据，达到内存上限或失效时禁止自动续取或重执行。

## 5. 空态、加载、失败与权限

| 状态 | 展示与行为 |
|---|---|
| 加载中 | 当前分区显示加载文案；无数据时不同时显示“没有待办” |
| 空态 | 当前分区一个紧凑空态，说明没有什么；不堆叠多个空标题和大块留白 |
| 失败 | 错误靠近对应列表或详情，保留已加载内容及重试路径；原始数据库错误保留原文 |
| 无选择 | 说明选择一项查看详情，不显示空 JSON、空命令或默认成功 |
| 只读观察 | 保留上下文，明确在哪个窗口处理；审批 / 认证动作禁用 |
| 已结束 | 显示实际终态，批准 / 拒绝等一次性动作不可再次发送 |
| 数据缺失 | “未记录”或“未知”，不把缺失数量当作 0、不使用猜测的连接或时间 |

## 6. 响应式、键盘与语言

- 宽屏保持原工作台结构；760px 及以下按原稿收起窄轨，内容区独立滚动。
- 对话框缩小到可用宽度；标签可换行，事实区改单列，主行文字可收缩，操作按钮不得被挤出视口。
- Tab 可到达所有启用操作，保留可见焦点；列表按钮支持宿主正常 Enter / Space 操作，不依赖仅鼠标交互。
- 文案、状态、tooltip、可访问名称支持简体中文和 English。连接名、对象、SQL、用户内容和原始错误不翻译。
- 语言切换不清除选择、表单、命令或分页状态。

## 7. 实施与验收

- 先在唯一 HTML 入口同步相同组件与状态，再对照真实 Tern 的布局；示例始终标识为预览，点击不能伪装真实审批、认证或执行。
- CSS 使用功能命名类，只影响目标组件，不全局覆盖 `button`、`p`、`pre` 或所有 overlay。
- 检查明暗主题、宽窄窗口、长名称、多条待办、空态、加载、错误、观察窗口、终态及可滚动长命令。
- 业务路径使用实际 Engine 和 MCP client 验证；截图来自真实渲染，保留在本地 `target/`，不提交到设计文档。

## 8. MCP 待办设计

### 8.1 信息架构

状态栏保留紧凑的“MCP 待办 (N)”文字入口，N 仅统计待处理审批与认证。点击打开与既有任务详情同层级的原生大号对话框，标题“MCP 待办”。

正文顶部为三个下划线标签：“待审批 (N)”“待认证 (N)”“Agent 任务”。只展示当前分区，首次打开优先进入有待处理项的分区；审批优先，其次认证，无待处理项默认审批。用户切换后的后台刷新不抢分区。

- **待审批**：平面列表主行显示操作标题与状态，副行显示真实连接 / 数据库。每行右侧放置拒绝（x）和批准（check）两个 quiet 图标按钮，均提供 tooltip 与可访问名称；与行选择按钮并列，禁止嵌套按钮。选择并加载冻结请求后，仅该行仍 pending、可决定且无在途操作时启用；只读观察显示原因。下方详情展示冻结目标、状态、到期时间、命令及独立参数，完整诊断默认折叠；footer 只保留关闭。
- **待认证**：每条显示连接名、认证状态、单独的控制窗口说明，右侧文字“认证”按钮；长名称不挤压操作。点击进入既有安全认证 overlay。其他窗口只能观察，动作禁用；不在列表中输入密码或 OTP。
- **Agent 任务**：列表主行显示操作名称与实际终态，连接 / 数据库等归属为副行；接口未提供摘要时使用通用任务标题与真实时间，选中后读取详情。结果沿用共享 grid 和分页器，明确“仅显示当前已返回的数据”，页数与下一页限定在已保留行范围内；观察不能触发 Agent 继续读取或重放查询。

### 8.2 视觉与行为约束

- 标题、标签、列表、详情、footer 各有清晰边界，沿用原设计的细线、8px 行内间距、16px 分区间距及 sans / mono 分工。
- 不展示大 UUID 按钮，不将 `pending`、`disconnected` 等协议值直接作为可见状态。
- 空态只针对当前标签；待认证有内容时不同时展示“没有审批”“没有任务”等无关空态。
- 加载审批详情时禁用批准 / 拒绝，旧详情不能决定新选择；处理结果以 Engine 返回状态为准，不在 UI 乐观执行。
- 刷新、选中、关闭、认证接手、批准 / 拒绝及观察结果继续使用现有 Engine 请求与所有权检查；本次视觉调整不新增权限或后台操作。
- HTML 示例覆盖审批详情、认证、任务结果、空态、观察窗口，以及未选择、加载、失败、审批终态和结果过期；示例提交仅显示“未发送”的预览说明。

## 9. 应用设置

- 设置仅设“常规”和“MCP”两个下划线 tab，默认常规；切换不丢草稿、连接选择或错误，也不触发保存。
- 全部设置项采用左 label、右值／控件的水平行。窄屏通过调整列宽、换行和正文滚动适配，仍保留左右关系，控件不挤出视口；语言、数字、策略、范围和已有规则均遵守此布局。
- 布尔设置使用原生 `ui::switch`；标签左对齐，开关在右。HTML 示例提供相同开关外观、可访问名称、checked 状态和键盘操作，不以方形 checkbox 替代。
- MySQL、Redis、Archery 连接表单与实例管理不展示 MCP 配置；各连接审批与细粒度权限统一从全局设置 MCP tab 的连接选择入口维护。普通连接编辑保留已有策略，新建连接采用全局默认。
- 常规区保留 Archery 服务管理；所有控件复用宿主 Field Row、Switch、Select 和按钮，不能通过全局 CSS 改写其他连接表单。
- dialog 底部 footer 只保留重新加载和保存，正文滚动时保持可见；保存使用原生 Primary 按钮，HTML 使用对应主按钮样式。关闭入口仅保留右上角 ×。
