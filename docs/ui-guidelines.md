# Datapier UI 设计规范

## 1. 适用范围与依据

本规范定义 Datapier 新增界面及既有界面调整的共同设计目标，依据已确认的交互决策、[UI 设计说明](ui-redesign.md)和[HTML 设计稿](ui-redesign.html)维护。保持数据库工作台紧凑、平面、内容优先的风格；规则适用于连接、资源、查询、数据编辑、设置与全部 dialog，不只适用于新增功能。

- 本文维护跨功能的视觉、组件、文案和交互约定。
- [UI 设计说明](ui-redesign.md)维护具体功能的操作语义；本文第 8 节记录 MCP 待办的布局与状态要求。
- [HTML 设计稿](ui-redesign.html)是唯一交互示例入口，示例不连接数据库，不代表执行或认证成功。
- 已确认的信息架构、操作语义与状态契约是设计依据；HTML 提供可交互示例，尺寸是默认对照值。原生使用公开 Tern SDK 和宿主主题绘制，允许字体度量、圆角、阴影等自然皮肤差异；不能以当前实现反向覆盖已确认的交互目标。
- 宿主能力不足时，在对应技术方案中记录目标、已验证限制、替代路径和未覆盖范围；不得声称只修改规范就已完成实现。规范与示例冲突时先同步具体设计，不能静默沿用旧入口或控件。
- 工程与验证规则见[贡献指南](../CONTRIBUTING.md)；来源、权限与执行边界沿用 [0.2.0 技术方案](technical-design-0.2.0.md)及 [0.3.0 技术方案](technical-design-0.3.0.md)。视觉一致不能扩大权限或改变提交语义。
- 像素、Tern 控件和 HTML 对照规则针对 TSP 工作台；普通终端 TUI 共用目标、草稿、权限、错误及保存语义，按终端能力提供等效键盘控件，不要求复刻 Switch 的图形皮肤。全量审查须另列 TUI 页面及不适用的视觉规则，不能将其混作原生控件差异。

## 2. 视觉原则

1. **内容优先**：连接名、对象、命令和结果是主体，装饰不能挤占工作区。
2. **平面分区**：用布局、间距、细分隔线区分区域；列表不套卡片，不用阴影制造多层容器。
3. **稳定层级**：标题、状态、摘要、详情、操作分层；禁止把独立字段连续拼成一行无间距文字。
4. **同义同形**：同一种状态、操作、选择和分页在不同功能里沿用相同表达。
5. **真实与克制**：不猜测结果、计数、权限、时间或成功状态；缺失信息显示“未记录”或“未知”。

## 3. 主题、字体与尺寸

### 3.1 颜色与字体

原生使用宿主语义 token；浏览器使用原稿的对应变量。禁止在业务组件里固定亮色、暗色或整块白底，也不全局重置宿主按钮和输入框。

| 用途 | HTML 对照 | 原生现有 token / 规则 |
|---|---|---|
| 主要文字 | `--fg` | `--t1` |
| 次要文字 | `--muted` | `--t3` |
| 面板与控件表面 | `--panel`、`--card` | 宿主 surface、`--card` |
| 分隔线 | `--border` | `--l2` |
| 选中、悬停 | `--selected`、`--hover` | `--tv-sel` 与已有 active 样式 |
| 强调、焦点 | `--accent` | `--accent` |
| 成功、警告、错误 | `--success`、`--warning`、`--error` | 沿用已有语义样式；状态同时有文字或形状 |
| 界面文字 | Geist / sans 回退 | `--sans` |
| SQL、Redis 命令、ID、数据 | `--mono` | `--mono` |

正文以 13px 为密集布局的 HTML 默认基准，数据以 11px 为基准；对话框标题约 15px、中等字重，分区标题约 12px，辅助信息约 11px。这些数值不是固定上限：跟随宿主字体与缩放增加行高和控件空间，不得以固定高度裁切文字；不要把状态栏的 10px 字号带入完整任务界面。长名称允许断行或省略，全文必须可通过键盘可达的详情、复制或 tooltip 取得，不能只依赖鼠标悬停。命令保留原始换行并使用等宽字体。

### 3.2 尺寸与间距

| 项目 | 原设计基准与使用规则 |
|---|---|
| 常规图标按钮 | 28px 热区、14px 图标；tooltip 与可访问名称齐全 |
| 原生按钮 | 高约 28px，使用宿主 quiet / default / primary / danger 变体 |
| 行内元素间距 | 通常 6–8px，不依靠文本中的空格排版 |
| 字段与分区间距 | 字段约 12–14px，分区约 16px；保持同页一致 |
| 连接行 | 最小约 44px，主名与副行对齐，操作保留固定空间 |
| 数据行 | 约 35px；Redis key 行约 34–36px |
| 展开导航 / 窄轨 | 224px / 58px |
| 上下文 / 标签 / 分区导航 | 最小约 54px / 39px / 28px |
| 状态栏 | 高约 29px，仅承载简短状态和轻入口 |
| 对话框 | 常规表单参考宽度约 720px；需要并排比较或编辑长正文时可使用宽版，仍受宿主可用空间约束；边缘默认至少留 20px，正文滚动、头尾可达 |
| 对话框内边距 | 标题约 14px 20px，正文约 18px 20px，底部约 12px 20px；原生由 SDK 绘制 |

### 3.3 可读性与可访问性底线

- 普通可读文字，包括辅助说明，以前景与实际背景至少 4.5:1 的对比度为目标；大号文字及辨认控件所必需的边界、状态标记以至少 3:1 为目标。禁用控件不等于说明文字也应难以辨认，不通过固定业务色覆盖宿主主题。
- 图标按钮默认 28px 热区可以保留；点击区域与图标绘制尺寸分开，避免密集相邻小目标。以至少 24×24 CSS px 的完整有效区域或符合要求的间距为底线，不能用“放大后可点击”代替检查。
- 默认及放大到 200% 的界面均应能阅读正文、操作关闭与主要动作；允许正文重排及表格、代码区域独立滚动，不要求数据库 grid 在窄屏取消横向滚动。宿主不能达到的缩放或辅助技术要求按第 1 节记录实际限制。
- 焦点态在明暗主题下清晰可见，不被固定表头、footer 或浮层遮挡；选中、错误、处理中及只读同时提供文字、形状或可访问状态，不能仅靠颜色。
- 数字设置说明单位、范围与留空语义；字节上限可提供可读容量说明，但不得静默改变原始值、精度或数据库内容。
- 对比度与目标尺寸参考 [WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)及 [2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)；这些是设计与验收目标，不代表当前宿主已通过全部可访问性验收。


## 4. 组件与操作语义

### 4.1 列表、标签与状态

- 连接、资源、任务选择行左对齐，平面背景，无按钮边框、圆角或阴影；悬停与选中使用底色和明确焦点态。
- 分区标签沿用工作台下划线活动态，不采用胶囊按钮或大型彩色卡片。
- 主行显示用户可识别的连接名、资源名或操作标题；地址、数据库、时间和简短 ID 放在副行或详情。
- 不以 UUID 或原始枚举作为唯一标题。状态翻译为“待审批”“待认证”“执行中”“已完成”“已拒绝”“已过期”等可读文案。
- 普通数据字段不按内容自动着色。状态使用语义色时仍显示文字，不能仅靠红绿区分。
- 连接类型、Archery 来源和连接状态沿用已有图标及角标语义，不互相替代。

### 4.2 按钮与危险操作

- quiet 用于辅助入口、切换和图标动作；default 用于关闭、返回、刷新等常规动作；primary 突出当前阶段的主要推进动作，例如准备预览、保存或提交。同一操作区域同时只突出一个可用主动作。
- danger 表达真实破坏性操作，不能把“拒绝审批”误画成删除数据。
- 一个操作区域保持明确主次；主提交居右，次操作在前。不能把多个按钮无间距嵌入状态文字。
- 图标动作需有 tooltip 和可访问名称；认证、保存等表单主操作保留文字，审批行内的批准与拒绝使用具名图标按钮。
- 按原因区分隐藏和禁用：来源或对象根本不支持的动作可隐藏；支持但因只读、权限、其他窗口控制、任务占用或详情未加载而暂不可用的动作保留禁用态及原因。不依靠禁用按钮本身的 hover 才能获知关键原因，也不隐藏目标和已有内容。

### 4.3 对话框与轻浮层

- 按任务选择容器：认证、短表单和一次确认使用原生 `overlay`，从界面 layer 挂载；需要持续编辑、跨资源切换或并排比较的工作使用 tab／工作区。MCP 待办与应用设置保持第 8、9 节的 dialog；批量替换和高级值编辑当前使用 dialog，复杂内容可按第 3.2 节使用宽版。调整既有容器须同步具体功能设计。
- 轻浮层仅承载简短说明，例如查询结果来源与限制；不得把完整工作流嵌进状态栏的绝对定位容器。
- 对话框复用 SDK 标题、关闭、遮罩、滚动和 footer，不仿造另一套外壳，不再通过放开状态栏 overflow 容纳正文。
- 标题、正文和操作区分离；目标摘要及主要动作位置稳定，避免操作随长表单滚到不可见。正文承担主要纵向滚动，长命令和表格仅在必要的内容区域独立滚动，不叠加多层同方向滚动容器。
- 同时只呈现一个交互主对话框；从待办进入认证时交接到既有安全认证表单，不叠放两层表单。
- Escape 优先关闭最内层下拉、菜单或轻浮层，再按第 4.6 节请求关闭当前 dialog；它与 ×／关闭按钮使用同一草稿和在途检查。关闭待办不批准、不拒绝，也不取消 Agent 任务。

### 4.4 详情与结构化数据

- 沿用任务详情的“标题与状态 → 摘要 → 命令 / 结果 / 错误”顺序。
- 摘要使用带分隔线的双列事实区；窄屏空间不足时变单列，标签弱化，值完整可读，详情正文可独立滚动。
- SQL / Redis 命令独立分区显示，绑定参数分开列出，不伪造插值后的执行文本。
- 完整请求、ID、digest、协议字段等技术诊断放在默认折叠的“完整诊断”中；首屏不直接铺内部协议 JSON。用户正在查看或编辑的 JSON 数据、SQL 和 Redis 内容属于主体，不受诊断折叠规则限制。
- 任务详情使用创建时冻结的连接、数据库与执行信息，不能借用当前标签制造上下文。敏感字段不得进入通知、列表或诊断展示。
- 结果复用现有 grid 与分页器，页大小在翻页按钮之前。过期、释放、未知列和不完整结果明确说明，不能显示假成功或自动重执行。
- 统一分页器的位置、页码、文案和交互，不强制所有来源使用相同候选数值。20／50／100／200／500／1000 是通用候选集，具体候选受来源能力、响应字节与内存预算约束；保留合法的当前自定义值，不支持的旧值明确提示调整，不能静默替换。请求返回上限与本地每页数量分别表达。未知总数不显示总页数或虚构总条数；安全实时源提供显式“统计总数”，单次结果只翻阅已保留数据，达到预算或失效时不自动续取或重执行。

### 4.5 表单与控件选择

| 用户意图 | 控件与状态要求 |
|---|---|
| 名称、主机、路径、短值 | 单行 Input；完整可读名称和字段标签对应，不为统一外观改成多行 Editor |
| 数值与限制 | 带数值校验的输入；说明单位、上下限及空值语义；按真实字段校验，错误就地关联 |
| 有限枚举与互斥选择 | Select 或具备单选语义的控件，显示可读选项；模式／内容分区才使用 tab，不用一排普通按钮暴露协议枚举 |
| 独立布尔开关 | Switch，包含连接“只读”、SSL／TLS、历史清理、通知及权限启用等；默认左 label、右开关，明确当前值和生效时机 |
| 多选数据库、行、列、成员或预览项 | 使用多选控件及 checked 状态，支持适用的全选、部分选择与键盘操作；不因统一 Switch 而把集合选择改成开关，不用 `☑` 字符冒充可访问选择状态 |
| SQL、长文本、JSON、XML、表达式 | 对应的多行 Editor／代码区，保留换行和适用的语法提示；Text／Hex 等模式不能改变值类型或偷偷格式化内容 |

- 独立布尔值在连接表单、设置、过滤条件等界面使用相同的 Switch 语义；“选中了哪些对象”与“功能是否开启”不得共用含义不清的控件。
- 所有可编辑控件具有可见标签及匹配的可访问名称；必填、条件必填、类型和空值规则见 [UI 设计说明](ui-redesign.md#mysql-数据与草稿)。错误靠近字段、保留输入并定位首个错误，不能只显示 toast。宿主尚不支持的原生 required 等状态必须如实记录。
- Switch 与其他输入都必须说明修改作用域：表单和应用设置修改本地草稿，显式保存后才生效；即时动作须有明确反馈，不能混入同一表单而让用户猜测。

### 4.6 草稿、关闭与危险确认

| 当前状态 | 关闭、返回、重新加载或切换目标的行为 |
|---|---|
| 无未保存修改 | 直接关闭或切换；保留具体功能约定的选择及阅读位置 |
| 有未保存设置、未应用值或编辑意图 | 优先保留可恢复的本地草稿；动作会丢弃输入或基线时进入确认步骤，明确提供“继续编辑”与“丢弃”，仅在确实支持时提供对应的保存／应用动作 |
| 请求、提交或文件操作在途 | 根据实际能力禁用会破坏归属的动作，或明确提供停止等待／取消；停止等待不能声称数据库操作已取消或回滚 |
| 结果未知、部分生效或需要重新核对 | 保留执行记录及用户新值，说明核对／恢复路径；关闭或重新打开不能自动重放 |

- ×、Escape、关闭、返回、刷新和批量关闭共用相同状态检查；关闭不会隐式提交数据库，也不会自动杀死外部编辑器。保存设置、应用到值会话、加入数据草稿与数据库提交必须使用各自名称。
- 当前已在 dialog 内时，丢弃确认通过同一 dialog 的确认步骤承接，返回后恢复输入与焦点；工作区危险确认可打开专用 dialog，同时只存在一个交互主 dialog。
- 数据删除、破坏性 DDL 和文件清理的最终确认显示冻结目标、实际影响及可恢复性，破坏性动作使用 danger。默认焦点放在安全动作或摘要，不默认触发危险执行；普通建表等操作不因属于 DDL 就一律标红。

## 5. 空态、加载、失败与权限

| 状态 | 展示与行为 |
|---|---|
| 加载中 | 当前分区显示加载文案；无数据时不同时显示“没有待办” |
| 空态 | 当前分区一个紧凑空态，说明没有什么；不堆叠多个空标题和大块留白 |
| 失败 | 错误靠近对应列表或详情，保留已加载内容及重试路径；原始数据库错误保留原文 |
| 无选择 | 说明选择一项查看详情，不显示空 JSON、空命令或默认成功 |
| 只读观察 | 保留上下文，明确在哪个窗口处理；审批 / 认证动作禁用 |
| 已结束 | 显示实际终态，批准 / 拒绝等一次性动作不可再次发送 |
| 数据缺失 | “未记录”或“未知”，不把缺失数量当作 0、不使用猜测的连接或时间 |

## 6. 响应式、键盘与语言

- 宽屏保持原工作台结构；760px 及以下按原稿收起窄轨，内容区独立滚动。
- 对话框缩小到可用宽度；内容分组和操作区可换行，事实区改单列，主行文字可收缩。普通设置保持水平行；复杂控件无法保留最小可用宽度时按第 9 节使用整行或上下布局，不能通过缩到不可读来维持列数。
- 键盘可到达所有启用功能，复合组件按组件规则导航，避免把每个树节点或表格单元格都简单加入页面 Tab 序列。不得依赖仅鼠标交互。
- dialog 打开时将焦点放入标题、首个合理输入或安全动作，Tab／Shift+Tab 在当前 dialog 内循环；关闭后返回触发入口，入口已不存在时回到逻辑上的后继位置。确认步骤返回原表单时恢复原焦点。参考 [WAI Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。
- 模式与分区 tab 支持方向键移动焦点、Home／End 定位首尾及 Enter／Space 激活；树使用方向键展开／收起及移动，菜单使用方向键、Enter 和 Escape。普通输入保留宿主文本编辑键，grid 的导航及编辑态 Tab 按 [既有快捷键规则](ui-redesign.md#快捷键与系统适配)执行，不互相抢键。
- 文案、状态、tooltip、可访问名称支持简体中文和 English。连接名、对象、SQL、用户内容和原始错误不翻译。
- 语言切换不清除选择、表单、命令或分页状态。

## 7. 实施与验收

- 新增或调整功能时同步唯一 HTML 入口中的目标组件和关键状态，再对照真实 Tern 布局与操作；示例始终标识为预览，不能伪装真实审批、认证或执行。规范更新仅表示设计目标，设计稿缺项与原生未对齐项分别记录，不能据文档改动声称界面已完成。
- 公共组件基线在公共样式中集中维护并限定 Datapier 作用域；HTML 的基础控件样式用于模拟宿主，原生不全局重置宿主皮肤。功能级修改使用功能命名类，不能新增裸 `button`、`p`、`pre` 或覆盖全部 SDK overlay 的规则来改变其他页面。
- 按页面及控件类型核对明暗主题、宽窄与短窗口、200% 缩放、长名称／译文、空态、加载、错误、观察窗口、终态及长命令；同时检查焦点、键盘、禁用原因和未保存关闭。全量审查应枚举全部入口及条件分支，给出覆盖范围、具体差异与未验证项，不能以抽查新增界面代表全工作台。
- 业务路径使用实际 Engine 和 MCP client 验证；截图来自真实渲染，保留在本地 `target/`，不提交到设计文档。

## 8. MCP 待办设计

### 8.1 信息架构

状态栏保留紧凑的“MCP 待办 (N)”文字入口，N 仅统计待处理审批与认证。点击打开与既有任务详情同层级的原生大号对话框，标题“MCP 待办”。

正文顶部为三个下划线标签：“待审批 (N)”“待认证 (N)”“Agent 任务”。只展示当前分区，首次打开优先进入有待处理项的分区；审批优先，其次认证，无待处理项默认审批。用户切换后的后台刷新不抢分区。

- **待审批**：平面列表主行显示操作标题与状态，副行显示真实连接 / 数据库。每行右侧放置拒绝（x）和批准（check）两个 quiet 图标按钮，均提供 tooltip 与可访问名称；与行选择按钮并列，禁止嵌套按钮。选择并加载冻结请求后，仅该行仍 pending、可决定且无在途操作时启用；只读观察显示原因。下方详情展示冻结目标、状态、到期时间、命令及独立参数，完整诊断默认折叠；footer 只保留关闭。
- **待认证**：每条显示连接名、认证状态、单独的控制窗口说明，右侧文字“认证”按钮；长名称不挤压操作。点击进入既有安全认证 overlay。其他窗口只能观察，动作禁用；不在列表中输入密码或 OTP。
- **Agent 任务**：列表主行显示操作名称与实际终态，连接 / 数据库等归属为副行；接口未提供摘要时使用通用任务标题与真实时间，选中后读取详情。结果沿用共享 grid 和分页器，明确“仅显示当前已返回的数据”，页数与下一页限定在已保留行范围内；观察不能触发 Agent 继续读取或重放查询。

### 8.2 视觉与行为约束

- 标题、标签、列表、详情、footer 各有清晰边界，沿用原设计的细线、8px 行内间距、16px 分区间距及 sans / mono 分工。
- 不展示大 UUID 按钮，不将 `pending`、`disconnected` 等协议值直接作为可见状态。
- 空态只针对当前标签；待认证有内容时不同时展示“没有审批”“没有任务”等无关空态。
- 加载审批详情时禁用批准 / 拒绝，旧详情不能决定新选择；处理结果以 Engine 返回状态为准，不在 UI 乐观执行。
- 刷新、选中、关闭、认证接手、批准 / 拒绝及观察结果继续使用现有 Engine 请求与所有权检查；本次视觉调整不新增权限或后台操作。
- HTML 示例覆盖审批详情、认证、任务结果、空态、观察窗口，以及未选择、加载、失败、审批终态和结果过期；示例提交仅显示“未发送”的预览说明。

## 9. 应用设置

- 应用设置分为“常规”“编辑与文件”“Archery”“MCP”四个下划线 tab，默认常规。切换保留草稿、连接选择、文件选择和错误，不触发保存；方向键、Home／End 与 Enter／Space 沿用统一 tab 契约。
- 常规承载语言、分页、读取／超时／内存限制及历史；编辑与文件承载编辑限制、外部编辑器和遗留文件；Archery 独立承载服务器管理；MCP 承载限制与审批、通知和连接权限。同一功能的开关、数值及说明放在一起。
- 普通设置默认左 label、右值／控件的水平行，复用宿主 Field Row；窄屏优先调整列宽、换行和正文滚动。长参数、规则编辑及其他复杂控件无法保证可读宽度时允许占整行或 label 在上，不强制所有内容保持双列。
- 布尔设置与连接只读、SSL／TLS 等独立开关统一使用原生 `ui::switch`；标签在左、开关在右。HTML 提供同等可访问名称、checked 状态和键盘操作，不以方形 checkbox 替代；数据库／行／列等多选仍按第 4.5 节处理。
- 应用设置是未保存草稿，修改 Switch 不立即改变生产配置；明显标识未保存修改，保存成功后才清除该标识，失败保留输入及错误。HTML 语言切换可即时用于预览并保存浏览器偏好，但须按示例边界说明，不冒充生产配置保存。
- 全局设置与所选连接的审批／权限若分别保存，必须分别标明保存范围及未保存状态；外层“保存设置”不能暗示会保存尚未提交的连接规则。选择审批策略不得在没有明确即时生效说明时直接写入生产配置。
- MySQL、Redis、Archery 连接表单与实例管理不展示 MCP 配置；各连接审批与细粒度权限统一从全局设置 MCP tab 的连接选择入口维护。普通连接编辑保留已有策略，新建连接采用全局默认。
- Archery tab 使用独立的服务器管理动作；服务器新增／编辑仍进入既有安全表单，不借“保存全局设置”暗示保存服务器。控件复用宿主 Field Row、Switch、Select 和按钮，不通过全局 CSS 改写连接表单。
- 常规编辑态 footer 保留重新加载和保存，正文滚动时保持可见；保存使用 Primary。× 是常规关闭入口，Escape 与其共用第 4.6 节检查；重新加载也须检查未保存修改。进入丢弃等确认步骤时使用该步骤的明确动作，不受常规 footer 两个按钮的数量约束。

## 10. 结构、替换和值编辑

- 新增界面使用平面分区、下划线 tab、结构化事实区与宿主控件；内部协议 JSON 不代替主要界面，用户 JSON 值仍可作为编辑主体。
- 既有表的结构浏览、编辑与草稿 DDL 预览复用该表的“结构”tab，保留库表上下文与草稿；不额外提供“设计结构”按钮或菜单项，也不另开设计 dialog。新建表、视图及触发器可使用独立工作台；危险执行前的二次确认遵循第 4.6 节。
- 结构使用“对象标签 → 结构 → 字段／索引／外键／CHECK／表选项”三级导航，编辑时增加“预览 DDL”；切换保留选中项、草稿及冻结计划，生成计划成功后自动切入 DDL 预览。字段 grid 分开显示类型下拉和长度，DECIMAL 在长度格填写 `18,4`，NULL 使用 checkbox，主键字段禁用，取消勾选时清除 NULL 默认值；默认值类型与值同一行。主键、外键使用有 tooltip 和可访问名称的 icon，快捷主键放在操作列并与索引草稿保持同源。索引在 grid 直接编辑名称、类型、可见性及有序列选择；索引所属表固定为当前表。外键在 grid 直接选择本表列、引用表和引用列，保留有序复合映射及更新／删除动作；候选来自真实元数据，加载、失败、已不可见的原值分别表达。表达式、前缀、排序及引用库等扩展属性仅随当前选中项显示，不重复主要输入。CHECK 和表选项使用紧凑属性 grid。上移、下移、删除统一放在行末操作列，稳定身份保证重排与草稿归属；不按序列化对象递归生成整页编辑器。
- 结构三级分区的新增入口使用 `plus` icon，并保留 tooltip 与可访问名称；字段、索引与外键的新增操作栏和上方 grid 统一间隔 `8px`。点击 grid 行的非控件热区切换选中项和下方扩展区；输入框、选择框与行内按钮保留各自操作，切换选中项不丢失当前输入或冻结计划。
- DATETIME、TIMESTAMP、TIME 的长度格编辑小数秒精度 `0–6`，默认 `0`；按真实类型读回精度，非法输入就地保留并阻止生成计划。
- 替换先显示真实目标、范围和条件，冻结后并列比较身份、原值、新值与包含状态；长值可按需读取。准备、丢弃和提交位置稳定，真实命令与有序参数分区显示，缺少完整数据时说明不可预览。
- 高级值编辑在模式 tab 前显示实际目标、只读状态及当前未应用／值会话状态；文件和外部编辑操作按生命周期分区，不根据当前活动表猜测已打开会话的目标。
- 定义、条件、预览、执行结果和完整诊断各有明确层级；SQL、参数和字节内容沿用等宽与独立滚动规则。
- 操作状态来自真实会话、计划、任务和本客户端所有权；只读、在途、未应用修改及失效状态有明确禁用反馈。
- 准备、应用到值会话、加入草稿与提交数据库分别表达；结果待确认、部分生效、冲突及验证不一致不得合并成成功。
- 具体操作与文件领取语义见 [UI 设计说明](ui-redesign.md#结构设计批量替换与高级值编辑)；HTML 示例中的提交和文件访问保持禁用。
