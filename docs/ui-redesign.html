设计依据与边界

RDBMS：参考 Tern Database

同一数据库工作区区分结构、数据与 SQL；采用紧凑工具栏、细分隔线、列级筛选和结果页脚。连接／数据库／表导航常驻左侧，长值编辑进入侧栏。

Redis：参考 RDM 与 RedisInsight

共享连接导航；key 列表与详情并排，类型、TTL 与当前 DB 始终可见。五种基础类型有各自的内容布局，CLI 在底部展开。

本轮保留的行为约束

  • RDBMS 首先落地 MySQL；Redis 保持单节点、五种基础类型。
  • 编辑形成草稿，显式提交；只读结果不呈现写入入口。
  • keyspace 树只组织已加载 key，不代表服务端目录或全库计数。
  • Redis 的字节、重复 List 值、无序 Set、ZSet score 与 TTL 不被通用表格语义覆盖。
  • 这是一份交互设计稿，没有数据库连接、SQL 或 Redis 命令执行。
